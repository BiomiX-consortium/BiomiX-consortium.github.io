Integration methods

SNF and NEMO integration workflows

Both methods group patients using similarities across continuous omics measurements. In Integration Options, enable integration and choose a method. Configure the run in Advanced options — SNF / NEMO.

SNF workflow NEMO workflow Validation and outputs

SNF workflow

  1. Match the samples. BiomiX retains patients present in every omics matrix and the metadata, and aligns their order across inputs.
  2. Prepare each omic. Remove features with missing values or zero variance. Optional variance filtering retains the highest-variance features. Enable scaling to z-score each retained feature across samples.
  3. Build patient similarity networks. Within each omic, SNF converts Euclidean distances into similarities using a scaled exponential kernel. N° neighbors defines the local neighborhood and Variance affinity matrix controls how similarity decays with distance.
  4. Fuse the networks. SNF repeatedly updates each omic network using its local neighborhoods and information from the other networks. N° iterations sets the number of message-passing rounds. The result is one fused patient similarity matrix.
  5. Cluster the patients. BiomiX applies spectral clustering to the fused matrix for each candidate number of clusters from 2 through Max cluster range. SNFtool uses the eigengap method (see SNFtool::estimateNumberOfClustersGivenGraph for details) to select an optimal number of clusters within that range.

Inspect the cluster assignments, validation results, and feature rankings.

NEMO workflow

  1. Choose which samples to retain. With Only common samples enabled, BiomiX aligns patients present in all omics and the metadata. Turn it off to retain patients with metadata who lack one or more omics. Every pair of retained patients must share at least one measured omic.
  2. Check partial overlap. When partial overlap is enabled, missing_samples_per_omic_NEMO.csv reports the percentage missing in each omic. BiomiX warns if an omic lacks more than 20% of samples. If a patient pair shares no omic, the run stops and nemo_pairwise_overlap_issues.csv identifies the affected pairs.
  3. Prepare each omic. Among the available samples, remove features with missing values or zero variance. Optionally filter by variance and z-score the retained features.
  4. Compute relative similarities. In each omic, NEMO converts Euclidean distances into affinities using a scaled exponential kernel, then evaluates each pair relative to its local neighborhoods. Set N° neighbors or leave it blank to derive it separately for each omic from its sample count divided by six.
  5. Integrate and cluster. For each patient pair, NEMO averages relative similarities over the omics measured in both patients. BiomiX applies spectral clustering to the integrated matrix for each number of candidate clusters from 2 through Max cluster range. NEMO selects the optimal number of clusters using its modified eigengap method. Rappoport and Shamir, Bioinformatics (2019).

Inspect the cluster assignments and available downstream analyses.

Validation, interpretation, and output files

Find each patient's cluster

Read the selected number of clusters in optimal_number_of_clusters.csv, then open clustering_results.csv to know which clusters patients are assigned across the number of clusters evaluated. Setting the maximum to 2 fixes the number of clusters at 2. If you supply reference labels through Condition column, their number of classes must fall within the candidate range or the run stops.

Assess cluster quality and stability

internal_quality_indices.csv file and internal_quality_indices.png plots report mean silhouette coefficient, Dunn index, entropy, and Calinski-Harabasz index for each candidate number of clusters. stability_results.csv reports stability for individual clusters across 100 resamplings, each using 80% of samples (Details in fpc::clusterboot)).

When reference labels are available (i.e. condition column), external_quality_indices.csv file and external_quality_indices.png image report agreement with those labels using ARI, AMI, NMI, and NVI for each number of clusters tested.

Inspect the networks

BiomiX saves each omic similarity matrix and the integrated matrix as CSV files. Similarity matrices are also showed using heatmaps, where patients are ordered by predicted groups and, when available, reference groups. Each corresponding network is showed has a static PNG image and an interactive HTML graph showing nearest-neighbor links (equal to N° neighbors). With reference labels, node color denotes the reference group and shape denotes the predicted cluster. Otherwise, color denotes the predicted cluster.

Identify features associated with the clustering

To rank features based on their importance, BiomiX builds a similarity matrix and clusters patients using each feature individually. It ranks features by normalized mutual information (NMI) between their individual feature assignments and the integrated clustering. Open feature_importance.csv for the scores and the per-omic heatmaps for z-scored values of the highest-ranked features. N° variables in heatmap sets how many features appear. NEMO produces these rankings and heatmaps only with Only common samples enabled.

Relate clusters to metadata and survival

For each selected enrichment variable, an alluvial plot shows its relationship to predicted clusters and any reference groups. BiomiX tests categorical variables with a chi-squared test and continuous variables with a Kruskal-Wallis test.

For survival analysis, supply a time and event column for each endpoint, such as A.time and A.event. BiomiX compares clusters with a log-rank test and produces a Kaplan-Meier plot for each endpoint and number of clusters. enrichment_survival_results.csv contains nominal and Benjamini-Hochberg-adjusted p-values for the enrichment of clinical variables and survival tests. Check enrichment_survival_results_warnings.csv for eventual statistical warnings.

Samples missing a value in clinical/survival variables are excluded from the corresponding test.
